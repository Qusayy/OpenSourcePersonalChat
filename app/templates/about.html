Everything here runs on one small server

No API key, no upstream provider, no GPU. {{ info.model }} at {{ info.quant }} on a {{ info.hardware }}, answering in the open with its own speed printed under every reply.

The stack

llama.cpp via llama-cpp-python holds the model — one instance, loaded once at startup and kept warm. FastAPI on a single uvicorn worker serves the pages and streams tokens over Server-Sent Events. SQLite in WAL mode stores conversations and every recorded run. The front-end is hand-written CSS and ES modules with no build step and no third-party JavaScript — the markdown renderer included.

Generation happens on a worker thread and tokens cross back to the event loop through a queue, so health checks, cancellation and other visitors' queue positions all keep responding while the model is busy.

One request at a time — on purpose

With two cores, two generations running side by side finish later than the same two run back to back: they fight over the same memory bandwidth and the same threads. So this server takes one at a time and shows you your place in the line. Honest queueing beats fake concurrency.

The lock is released by the generation thread itself, in its own finally. Releasing it from the request handler would let a disconnecting client hand the slot to the next visitor while llama.cpp was still mid-token.

Getting the prompt right matters more than the sampler

An instruct model fed raw text behaves like a base model: it rambles, it repeats, it never stops cleanly. The usual reaction is to clamp the sampler down to near-greedy and bolt on a loop that detects repeated sentences — which makes the repetition worse, because greedy decoding is exactly what produces loops.

The fix is the chat template. Every turn goes through the <|im_start|> / <|im_end|> format the model was fine-tuned on, so it stops on its own token, and sampling can sit at a normal temperature 0.7 with a light repeat_penalty. No dedup hack required.

What it cannot do

It is a 1.5-billion-parameter model quantised to four bits. It will get arithmetic wrong, invent citations, lose the thread on long reasoning chains, and know nothing about anything recent. It is good at short explanations, quick drafts, summarising what you paste in, and simple code — and it answers in a couple of seconds without sending a byte off this machine.

The context window is {{ info.n_ctx }} tokens. Older turns are trimmed automatically when a conversation outgrows it; the system prompt is always kept.
